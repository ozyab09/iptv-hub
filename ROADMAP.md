# ROADMAP — IPTV Hub

> Статус после v0.2.3 (сентябрь 2026). История изменений — в git и GitHub Issues;
> актуальный план — здесь. Прежде чем брать задачу: issue → ветку → PR (см. AGENTS.md).

## Где мы сейчас

Из MVP «парсер + список + HLS» вырос полноценный плеер:

- **Плейлисты**: несколько источников, менеджер с инлайн-редактором
  (без prompt), ленивая миграция со старого конфига, `?p=` апсертит,
  избранное per-плейлист, экспорт/импорт настроек (versioned JSON)
- **Плеер**: hls.js + нативный fallback, пауза/громкость/prev-next,
  PiP, перемотка ±15с (архив/VOD), выбор качества кнопкой с живым лейблом
  (Auto·FHD/HD/SD), аудио/субтитры кнопками с меню в теме сайта,
  нативный fullscreen с сохранением транспортных контролов,
  автовосстановление network/media ошибок + retry-кнопка ↻; при фатальной
  ошибке плеер называет её причину, а http-каналы на https-странице
  автоматически спасает апгрейдом на https-порт (PR#63, #68)
- **Запись эфира**: HLS пишется сегментами без перекодирования (PR#61),
  звук захватывается прямо с `<video>` (fallback — канвас без звука),
  сорвавшаяся запись не выдаётся за готовый файл (PR#60), тост-кнопка
  скачивания для Firefox/Zen
- **EPG**: сейчас/далее в списке, модалка-гайд с вкладками дней,
  catchup-архив до 3 дней (tvg-rec/catchup-source, {utc}/{lutc}/…)
- **UX**: тёмная/светлая темы (системный дефолт, без FOUC), PWA
  (оффлайн-shell + кэш плейлиста/EPG), горячие клавиши (space/←→/↑↓/M/J/L/F),
  поиск, категории, избранное, «недавно просмотренные» (10 чипов),
  виртуализированный список (~2600 каналов, в DOM только видимое окно;
  спейсер учитывает колонки сетки), мобильный портрет без наезда контролов —
  зоны плеер-бара в столбец, touch-цели ≥ 40px, safe-area, bottom-sheet гайд (PR#64),
  экранный лог по `?debug=1` для отладки на телефоне
- **Инфраструктура**: 155 юнит-тестов, CI (Node 22, actions v5) с required
  check `build`, branch protection на main, деплой Pages из main

## Честный анализ: чего не хватает

### P1 — заметные пробелы в том, что уже заявлено

1. **Гайд без «занятости».** EPG до 200MB распакованных парсится в память —
   гигантские файлы на слабых устройствах. Индексация по каналам при парсинге
   + переход на стриминговое чтение из IndexedDB, если подтвердится проблема.
2. **Ошибка без diagnostics при CORS-блокировке потока.** Плеер называет
   mixed content и HTTP-статусы, но «подозрение на CORS» — гадание по
   косвенным признакам; стоит один раз подтвердить через `fetch` HEAD и
   показать точную причину с чек-листом (как для плейлиста).

### P2 — качество жизни

3. **Мини-миниатюра**: тег `<video>` в списке каналов при hover — тяжело;
   альтернатива: логотип канала уже есть, добавить текстовый превью-тост.
4. **Клавиатурная навигация по списку** (↑/↓ + Enter), skip-link, полный
   aria-аудит модалок (фокус-ловушка, возврат фокуса).
5. **Локализация en/ru** — строки уже изолированы не везде, собрать в словарь.
6. **Визуальная проверка вёрстки в CI** (Playwright-скриншоты мобильного
   портрета/пейзажа) — регрессию #62 поймал только ручной тест.
7. **Предупреждение о http-каналах в списке** — значок ⚠ у каналов с
   http-URL: пользователь видит проблему до клика, а не после тоста.
8. **Автовозврат к позиции VOD/catchup** — «недавние каналы» помнят URL,
   но не позицию воспроизведения; хранить `currentTime` и продолжать.
9. **Тесты на upsert-сценарии `?p=`** — с `playlists.test.ts` база есть,
   но связка «ссылка с `e=` на существующий плейлист обновляет EPG» стоит
   явного теста (регрессия #71 была именно в расхождении docs/кода).

### P3 — платформа

10. **Кастомные эмодзи-пары из родительского `iptv`** (FNV-1a по URL) для
    визуального различения каналов — консистентность с пайплайном.
11. **Android TV-компаньон** (Kotlin + WebView на этот же сайт, D-pad-карта
    клавиш). Сайт уже mobile-first, но focus-стили под D-pad надо доделать (см. 4).
12. **DASH-адаптер** (dash.js) за проверкой формата — редкие провайдеры.
13. **Share-target** в PWA-манифесте: «поделиться» ссылкой на плейлист из
    другого приложения прямо в IPTV Hub (`?p=`-upsert уже готов принять её —
    остался манифест + обработка share).
14. **Фильтр «скрыть каналы с http»** — настройка per-плейлист для тех,
    кто сидит на https и не хочет видеть неиграбельные каналы.
15. **Отложенное**: мульти-audio в PiP (платформенное ограничение), Chromium
    API Media Sessions для кнопок гарнитуры — проверить объём работы.

## Не делать (осознанные решения, см. AGENTS.md)

- Серверный прокси/бэкенд — ломает модель статики.
- Кэширование медиа-сегментов — живой ТВ в оффлайне не существует.
- Сторонние UI-кит и аналитика — privacy-first, bundle уже 190KB gzip
  из-за hls.js; новые runtime-зависимости — только через обсуждение.

## Практика выпуска

- Версию bump'им в `package.json` + `VERSION` в `public/sw.js` одновременно
  (кэши SW версионированы, иначе клиенты застрянут на старом shell).
- Каждое изменение — через issue → ветку → PR → зелёный `build` → merge.
- Перед merge: `npm test` (155 тестов) + `npm run build` локально зелёные.
