# ROADMAP — IPTV Hub

> Статус после v0.9 (сентябрь 2026). История изменений — в git и GitHub Issues;
> актуальный план — здесь. Прежде чем брать задачу: issue → ветка → PR (см. AGENTS.md).

## Где мы сейчас

Из MVP «парсер + список + HLS» вырос полноценный плеер:

- **Плейлисты**: несколько источников, менеджер (rename/delete/switch),
  ленивая миграция со старого конфига, `?p=` апсертит, избранное per-плейлист
- **Плеер**: hls.js + нативный fallback, пауза/громкость/prev-next,
  PiP, перемотка ±15с (архив/VOD), выбор качества кнопкой с живым лейблом
  (Auto·FHD/HD/SD), аудио/субтитры при наличии, запись эфира в локальный файл
- **EPG**: сейчас/далее в списке, модалка-гайд с вкладками дней,
  catchup-архив до 3 дней (tvg-rec/catchup-source, {utc}/{lutc}/…)
- **UX**: тёмная/светлая темы (системный дефолт, без FOUC), PWA
  (оффлайн-shell + кэш плейлиста/EPG), горячие клавиши, поиск, категории,
  избранное
- **Инфраструктура**: 99 юнит-тестов, CI (Node 22, actions v5) с required
  check `build`, branch protection на main, деплой Pages из main

## Честный анализ: чего не хватает

### P1 — заметные пробелы в том, что уже заявлено

1. **Виртуализация списка каналов.** ~2600 карточек рендерятся в DOM целиком —
   на слабых устройствах листание/поиск подлагивают. Нужен windowing
   (например, собственный на основе IntersectionObserver, без зависимостей).
2. **Аудио/субтитры всё ещё `<select>`.** Качество уже кнопкой с меню в теме
   сайта — дорожки должны переехать туда же (компонент-меню общий).
3. **Ошибки без восстановления.** Упавший поток/EPG показывают тост, но нет
   retry-кнопки в player bar и авто-переподключения hls.js (startLoad/-1).
4. **Гайд без «занятости».** EPG до 200MB распакованных парсится в память —
   гигантские файлы на слабых устройствах. Индексация по каналам при парсинге
   + переход на стриминговое чтение из IndexedDB, если подтвердится проблема.
5. **Менеджер плейлистов на prompt().** Работает, но выглядит дёшево:
   инлайн-редактирование в карточке (как у качества — компонент-меню).

### P2 — качество жизни

6. **Экспорт/импорт всего набора** (плейлисты + избранное + тема) в JSON —
   бэкап и перенос между устройствами. Ключи уже изолированы, экспорт простой.
7. **«Последние каналы»** (recently watched, 10 шт.) над списком + кнопка
   «продолжить с места остановки» для VOD/catchup.
8. **Мини-миниатюра**: тег `<video>` в списке каналов при hover — тяжело;
   альтернатива: логотип канала уже есть, добавить текстовый превью-тост.
9. **Клавиатурная навигация по списку** (↑/↓ + Enter), skip-link, полный
   aria-аудит модалок (фокус-ловушка, возврат фокуса).
10. **Локализация en/ru** — строки уже изолированы не везде, собрать в словарь.

### P3 — платформа

11. **Кастомные эмодзи-пары из родительского `iptv`** (FNV-1a по URL) для
    визуального различения каналов — консистентность с пайплайном.
12. **Android TV-компаньон** (Kotlin + WebView на этот же сайт, D-pad-карта
    клавиш). Сайт уже mobile-first, но focus-стили под D-pad надо доделать (см. 9).
13. **DASH-адаптер** (dash.js) за проверкой формата — редкие провайдеры.
14. **Share-target** в PWA-манифесте: «поделиться» ссылкой на плейлист из
    другого приложения прямо в IPTV Hub.
15. **Отложенное**: мульти-audio в PiP (платформенное ограничение), Chromium
    API Media Sessions для кнопок гарнитуры — проверить объём работы.

## Не делать (осознанные решения, см. AGENTS.md)

- Серверный прокси/бэкенд — ломает модель статики.
- Кэширование медиа-сегментов — живой ТВ в оффлайне не существует.
- Сторонние UI-кит и аналитика — privacy-first, bundle уже 190KB gzip
  из-за hls.js; новые runtime-зависимости — только через обсуждение.

## Практика выпуска

- Версию bump'им в `package.json` + `VERSION` в `public/sw.js` одновременно
  (кэши SW версионированы, иначе клиенты застрянут на старом shell).
- Каждое изменение — через issue → ветку → PR → зелёный `build` → merge.
- Перед merge: `npm test` (99 тестов) + `npm run build` локально зелёные.
