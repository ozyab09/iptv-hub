## Где мы сейчас

Из MVP «парсер + список + HLS» вырос полноценный плеер с дизайн-системой v2:

- **Редизайн v2** (PR#74): токены, линейные иконки, пять равноправных
  разделов (каналы / избранное / недавние / **записи** / настройки) — таб-бар
  на телефоне, сайдбар на десктопе; полоса хода передачи с «К эфиру»; блок
  «Продолжить просмотр»; жесты на кадре (свайп — канал, двойной тап — ±15с)
- **Плейлисты**: несколько источников, менеджер с инлайн-редактором,
  ленивая миграция со старого конфига, `?p=` апсертит, `?ch=` — диплинк
  на канал, **локальный плейлист из файла (OPFS)** — работает без сети,
  избранное и «недавние» per-плейлист, экспорт/импорт настроек с «недавними»
  (versioned JSON), экспорт избранного в `.m3u`, кросс-таб синхронизация
  через `storage`-событие
- **Плеер**: hls.js + нативный fallback, пауза/громкость/prev-next,
  PiP, перемотка ±15с, **продолжение VOD/catchup с последней позиции**,
  выбор качества/аудио/субтитров кнопками с меню в теме сайта,
  нативный fullscreen, автовосстановление ошибок + retry; при фатальной
  ошибке плеер называет причину — mixed content, HTTP-статус, **диагностика
  CORS контрольным запросом** с чек-листом; http-каналы на https-странице
  спасаются апгрейдом на https-порт
- **Запись эфира**: HLS — сегментами без перекодирования, сорвавшаяся запись
  не выдаётся за готовый файл; **библиотека записей** — панель со списком,
  воспроизведение и скачивание из приложения
- **EPG**: сейчас/далее в списке, гайд с вкладками дней, catchup-архив
  до 3 дней, автоподстановка EPG из заголовка плейлиста, гонка загрузок
  устранена гардом (`latest.ts`)
- **UX**: темы, PWA (оффлайн-shell + кэш данных), горячие клавиши,
  **клавиатурная навигация по списку**, поиск, категории, избранное,
  «недавно просмотренные», виртуализированный список (~2600 каналов),
  **мини-превью «сейчас в эфире»** по hover/long-press, **кнопка «назад»
  закрывает оверлеи** (overlays в history), **Wake Lock** на время просмотра,
  **sleep-таймер** (30/60/90 мин / конец передачи), **скриншот кадра в PNG**,
  экранный лог по `?debug=1`; колокольчик уведомлений с историей
- **Android**: TWA-обёртка (Bubblewrap) с автопубликацией APK через GitLab CI,
  версия приложения из `public/version.json`
- **Инфраструктура**: юнит-тесты без DOM и сети (39 файлов, счётчик в CI),
  CI (Node 22, пин ubuntu-24.04) с required check `build` **и job `visual`** —
  Playwright/chromium smoke-проверки вёрстки (мобильный портрет/пейзаж,
  десктоп, перекрытия контролов) против прода-сборки; branch protection,
  деплой Pages из main

### FR-16. Поиск по передачам EPG (P2)

**Требование.** Поиск ищет не только каналы, но и передачи: строка запроса
матчится по названиям программ в EPG активного плейлиста, результат — список
«канал · передача · время» с переходом к каналу (и в catchup, если передача
прошла). Поиск по каналам сохраняется как есть.

**Критерий приёмки.** «Футбол» находит передачи по слову в названии;
переход из результата включает канал; без EPG — поиск по каналам работает
как раньше. Матчинг — чистая функция с тестами.

### FR-17. Управление группами: скрытие и порядок (P2)

**Требование.** Группы каналов можно скрыть (per-плейлист, localStorage) и
переставить; скрытые не попадают в список, чипы категорий и счётчики.
Сброс — кнопкой «показать все».

**Критерий приёмки.** Скрытая группа исчезает из всех разделов и не участвует
в «сейчас/далее» выборке; состояние переживает перезагрузку; логика фильтрации
— чистая функция с тестами (views.ts расширяется).

### FR-18. ZAP по номеру канала (P2)

**Требование.** Цифровой ввод на странице плеера (0–9) собирает номер канала
и через ~1с бездействия включает канал с этим порядковым номером в текущем
отсортированном списке; оверлей показывает набираемое число.

**Критерий приёмки.** «2» «5» → канал №25; номер вне диапазона — тост;
смена канала не сбивает запись; логика набора (окно, таймаут) — чистый модуль
с тестами.

### FR-19. Xtream Codes API (P2)

**Требование.** В менеджере плейлистов — третий тип источника: `host`,
`username`, `password` (Xtream Codes, как у TiviMate/Kodi). Приложение само
строит `get_live_streams` → M3U и `get_short_epg`/`get_simple_data_table` →
XMLTV-подобный индекс; все запросы https, ключи — в localStorage.

**Критерий приёмки.** Провайдер с Xtream подключается без ручного M3U-URL;
каналы + EPG + catchup работают как у обычного плейлиста; URL-клиент
(`?p=`) не регрессирует; построение запросов и разбор ответа — чистые модули
с тестами (фейковый fetch). Не поддерживаем: vod/series-разделы Xtream (первый
этап — только live).

### FR-20. Записи по расписанию (P3)

**Требование.** Из гайда — «записывать эту передачу» и «записывать каждый
день/по будням»: приложение в фоне (пока вкладка открыта) по расписанию
начинает запись сегментами в момент старта передачи и останавливает по
окончании; серия управляется из «Записей».

**Критерий приёмки.** Запланированная запись стартует сама при открытом
приложении; правило серии редактируется и удаляется; планировщик — чистый
модуль с тестами (фейковый таймер); закрытая вкладка = записи нет (честно
в документации — zero backend).

### FR-21. Timeshift живого эфира (P3)

**Требование.** Пауза живого HLS не теряет буфер: после паузы перемотка назад
в пределах буфера работает, «К эфиру» возвращает в конец. Опционально —
«сдвиг эфира на N минут» из меню.

**Критерий приёмки.** Пауза 3 минуты → продолжение с места паузы, а не с
«конца»; «К эфиру» возвращает в live; поведение на нативном playback — без
регрессий.

### FR-22. Зеркала каналов (P3)

**Требование.** M3U-строки с одинаковым `tvg-id` (или список URL через
`|` в нестандартных плейлистах) считаются зеркалами одного канала: при
фатальной ошибке первого URL плеер пробует следующее зеркало, не показывая
пользователю ошибку.

**Критерий приёмки.** Канал с двумя зеркалами выживает при падении первого;
дедуп парсера не склеивает зеркала (группа по tvg-id, не по URL); fallback —
чистая логика с тестами.

### FR-23. Родительский PIN на группы (P3)

**Требование.** На группу каналов можно поставить PIN (хеш в localStorage):
вход в группу и открытие её каналов требуют ввода, «снять PIN» — тоже.
Забыл PIN — только полный сброс настроек (честно в документации).

**Критерий приёмки.** Закрытая группа не открывается без PIN, включая
`?ch=`-диплинк и ZAP; PIN хранится как хеш, не в открытом виде; логика
проверки — чистая функция с тестами.

### FR-24. Переименование и скрытие каналов (P3)

**Требование.** Контекстное действие на канале: переименовать (локальный
алиас per-плейлист) и скрыть (не показывать в списке, но искать по `?ch=`).
Сброс — в настройках.

**Критерий приёмки.** Алиас виден в списке, поиске и плеер-баре; скрытый
канал не попадает в списки, но продолжает играть по диплинку; хранение —
per-плейлист, тесты на apply-логику.

### FR-25. Мульти-вью 2×2 (P3, с осторожностью)

**Требование.** До 4 каналов одновременно в сетке на десктопе (MSE
позволяет несколько `<video>`). Обязательна деградация: на мобильных и при
`document.concurrency`-недоступности — тост «не на этом устройстве».

**Критерий приёмки.** 4 HLS-потока играют синхронно с звуком активного;
переключение сетки/одиночки — без утечек (все hls-инстансы закрываются);
на слабых устройствах — явный отказ. Риск батареи задокументирован.

### FR-26. Локализация en/ru (P2)

**Требование.** Словарь `src/i18n.ts` (ru/en), язык по `navigator.language`
с переключателем в настройках, выбор в localStorage. Первыми переводятся
настройки, менеджер, колокольчик и ошибки; тексты EPG и плейлистов не
переводятся никогда.

**Критерий приёмки.** Интерфейс переключается без перезагрузки; тест на
полноту ключей (en/ru синхронны); `t(key)` — чистая функция.

### FR-27. Расширенные настройки плеера (P3)

**Требование.** В настройках — раздел «Плеер»: размер буфера hls.js
(`maxBufferLength`), low-latency режим, таймаут диагностики. Значения по
умолчанию — как сейчас; изменения применяются к следующему каналу.

**Критерий приёмки.** Увеличенный буфер держит паузу дольше (см. FR-21);
некорректные значения отбрасываются санитайзером; чистый модуль настроек
с тестами.

## Честный анализ: чего не хватает

Живой план после закрытия FR-1…FR-15.

### P1 — долги

1. **EPG в память целиком.** До 200MB распакованных парсится в память —
   гигантские файлы на слабых устройствах. Индексация по каналам при парсинге
   + стриминговое чтение из IndexedDB, если подтвердится проблема.
2. **Рефакторинг `main.ts` (3315 строк, идёт).** Срезы: колокольчик
   (`notification-bell.ts`), меню качества (`quality-menu.ts`) — готовы;
   дальше менеджер плейлистов, транспорт, рендеры каналов/гайда. Срез —
   один PR, поведение не меняется.

### P2 — качество жизни

3. **FR-16 Поиск по передачам** — главный пробел поиска.
4. **FR-17 Управление группами** — TiviMate-стиль: скрыть/переставить.
5. **FR-18 ZAP по номеру** — классика IPTV, дёшево.
6. **FR-19 Xtream Codes** — самый популярный формат провайдеров, которого
   у нас нет.
7. **FR-26 Локализация** — вернулась из отложенного: срезы рефакторинга
   изолировали достаточно строк, чтобы делать словарь без вечных конфликтов.

### P3 — платформа и идеи

8. **FR-20 Записи по расписанию** — надстройка над библиотекой записей.
9. **FR-21 Timeshift** — пауза живого эфира с перемоткой буфера.
10. **FR-22 Зеркала каналов** — fallback URL при падении потока.
11. **FR-23 Родительский PIN**, **FR-24 Переименование/скрытие каналов** —
    персонализация per-плейлист.
12. **FR-25 Мульти-вью** — с осторожностью (батарея, декодеры).
13. **FR-27 Расширенные настройки плеера** — буфер/latency для энтузиастов.
14. **Напоминания о передаче** — «напомнить за 5 минут» из гайда. Пока
    открыта вкладка — таймер; Notification API под вопросом (permission).
15. **Кастомные эмодзи-пары из родительского `iptv`** (FNV-1a по URL) для
    визуального различения каналов — консистентность с пайплайном.
16. **Android TV-компаньон** — D-pad-карта поверх TWA (#167); сначала
    фокус-стили (FR-8 готов, осталось довести до идеала под D-pad).
17. **DASH-адаптер** (dash.js) за проверкой формата — редкие провайдеры.
18. **Share-target** в PWA-манифесте: «поделиться» ссылкой на плейлист
    прямо в IPTV Hub (`?p=`-upsert готов принять, `?ch=` — канал).
19. **Отложенное**: мульти-audio в PiP (платформенное ограничение),
    Media Sessions для кнопок гарнитуры — проверить объём работы.

## Не делать (осознанные решения, см. AGENTS.md)

- Серверный прокси/бэкенд — ломает модель статики.
- Кэширование медиа-сегментов — живой ТВ в оффлайне не существует.
- Сторонние UI-кит и аналитика — privacy-first; новые runtime-зависимости —
  только через обсуждение.
- Пробинг каналов клиентом в фоне — задача родительского пайплайна
  (`PROBE_SOURCES=true`); одиночная диагностика при ошибке (FR-5) — не
  пробинг, ок.

## Практика выпуска

- VERSION в `public/sw.js` штампуется хэшем сборки автоматически; версия
  пакета синхронна с доками — тест `tests/version.test.ts` следит за
  расхождением (CI). `public/version.json` питает автообновление TWA.
- Каждое изменение — через issue → ветку → PR → зелёный `build` (+ `visual`)
  → merge.
- Перед merge: `npm test` + `npm run build` локально зелёные.
- В доках не фиксировать точное число тестов — врёт быстрее кода.
