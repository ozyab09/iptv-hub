## Где мы сейчас

Из MVP «парсер + список + HLS» вырос полноценный плеер с дизайн-системой v2:

- **Редизайн v2** (PR#74): токены, линейные иконки, четыре равноправных
  раздела (каналы / избранное / недавние / настройки) — таб-бар на телефоне,
  сайдбар на десктопе; полоса хода передачи с «К эфиру»; блок «Продолжить
  просмотр»; жесты на кадре (свайп — канал, двойной тап — ±15с)
- **Плейлисты**: несколько источников, менеджер с инлайн-редактором
  (без prompt), ленивая миграция со старого конфига, `?p=` апсертит,
  избранное per-плейлист, экспорт/импорт настроек (versioned JSON)
- **Плеер**: hls.js + нативный fallback, пауза/громкость/prev-next,
  PiP, перемотка ±15с (архив/VOD), выбор качества кнопкой с живым лейблом
  (Auto·FHD/HD/SD), аудио/субтитры кнопками с меню в теме сайта,
  нативный fullscreen с сохранением транспортных контролов,
  автовосстановление network/media ошибок + retry-кнопка ↻; при фатальной
  ошибке плеер называет её причину, а http-каналы на https-странице
  автоматически спасает апгрейдом на https-порт (PR#63, #68)
- **Запись эфира**: HLS пишется сегментами без перекодирования (PR#61),
  звук захватывается прямо с `<video>` (fallback — канвас без звука),
  сорвавшаяся запись не выдаётся за готовый файл (PR#60), тост-кнопка
  скачивания для Firefox/Zen
- **EPG**: сейчас/далее в списке, модалка-гайд с вкладками дней,
  catchup-архив до 3 дней (tvg-rec/catchup-source, {utc}/{lutc}/…)
- **UX**: тёмная/светлая темы (системный дефолт, без FOUC), PWA
  (оффлайн-shell + кэш плейлиста/EPG), горячие клавиши (space/←→/↑↓/M/J/L/F),
  поиск, категории, избранное, «недавно просмотренные» (10 чипов),
  виртуализированный список (~2600 каналов, в DOM только видимое окно;
  спейсер учитывает колонки сетки),  мобильный портрет без наезда контролов —
  зоны плеер-бара в столбец, touch-цели ≥ 40px, safe-area, bottom-sheet гайд (PR#64),
  экранный лог по `?debug=1` для отладки на телефоне;
  ползунок громкости больше не наезжает на правую группу кнопок деки (issue #155,
  smoke-тестом в CI)
- **Обновление данных**: PWA обновляется сама (версия SW штампуется хэшем
  сборки, вкладка перезагружается по контроллеру или тостом «Обновить»);
  плейлист перепроверяется по расписанию или кнопкой «Проверить сейчас»
  (сейчас/каналы/передачи — отчётом в колокольчик), EPG подтягивается
  из заголовка плейлиста и обновляется вместе с ним; неиграбельные
  http-каналы публичных хостов скрываются при разборе (приватные — остаются)
- **Центр уведомлений**: колокольчик в шапке с бейджем непрочитанных,
  история до 20 уведомлений в localStorage (скрытые http, итоги проверки)
- **Инфраструктура**: 313 юнит-тестов, CI (Node 22, actions v5) с required
  check `build`, branch protection на main, деплой Pages из main

## Функциональные требования (бэклог)

Формализация задач из этого плана: у каждой — требование и критерий
приёмки. Нумерация FR-сквозная, статус обновляется по мере реализации.
Каждая реализация — через issue → ветку → PR (см. AGENTS.md).

### FR-1. Перенос «недавних» в экспорт/импорт (P1)

**Требование.** Экспортируемый JSON включает `recents: Record<playlistId, string[]>`
(те же `iptv-hub.recents.v1:<id>`, ≤10 URL на плейлист). Импорт принимает файлы
и без `recents` (старые бэкапы), некорректные URL внутри — отбрасываются.

**Критерий приёмки.** Экспорт → импорт на «чистом» браузере восстанавливает
раздел «Недавние» и блок «Продолжить просмотр»; `version` остаётся 1; тест
кругового перехода в `backup.test.ts` зелёный.

### FR-2. Миграция легаси-избранного (P1)

**Требование.** Если есть глобальный `iptv-hub.favorites.v1` (до
мультиплейлистов) — при загрузке его URL переносятся в
`iptv-hub.favorites.v1:<id>` первого (активного/единственного) плейлиста;
миграция идемпотентна, старый ключ не удаляется.

**Критерий приёмки.** Апгрейд со старой версии не теряет ни одного
избранного; повторная загрузка не дублирует записи; тест в `favorites.test.ts`.

### FR-3. Актуальность EPG при переключении плейлистов (P1)

**Требование.** Загрузка EPG привязана к конкретному плейлисту: поздний ответ
устаревшей загрузки не применяется (guard по id плейлиста или AbortController).

**Критерий приёмки.** Чистая логика загрузки покрыта тестом «быстрые
переключения A→B: итоговый epg соответствует B»; в UI гайд и «сейчас/далее»
всегда от активного плейлиста.

### FR-4. Синхронизация версии пакета с релизом (P1)

**Требование.** `package.json` бампится при каждом релизе; в CI есть проверка,
что версия пакета не отстаёт от упомянутой в доках (или скрипт, печатающий
расхождение и падающий сборку).

**Критерий приёмки.** CI падает, если `package.json` и доки расходятся.

### FR-5. Диагностика CORS-блока потока (P1)

**Требование.** При фатальной ошибке воспроизведения с признаками CORS плеер
делает одиночный контрольный `fetch` (HEAD/GET без чтения тела) к потоку и
показывает точную причину: «поток без CORS-заголовков» с чек-листом, как для
плейлиста. Контрольный запрос не ретраится и не блокирует UI.

**Критерий приёмки.** Канал без CORS даёт сообщение с явной причиной, а не
гадание «подозрение на CORS»; логика выбора формулировки — чистая функция
с тестами.

### FR-6. Кнопка «назад» закрывает оверлеи, а не приложение (P2)

**Требование.** Открытие плеера, гайда, менеджера плейлистов, меню качества
и центра уведомлений кладёт запись в history; `popstate` закрывает верхний
оверлей. Повторное «назад» на пустом экране — стандартное поведение браузера.

**Критерий приёмки.** На Android свайп «назад» при открытом плеере/гайде
возвращает к списку, приложение не закрывается; глубина стека не растёт
при повторных открытиях одного оверлея.

### FR-7. Wake Lock во время просмотра (P2)

**Требование.** Пока видео играет и вкладка видима — удерживать
`wakeLock.request("screen")`; на pause/stop/скрытие вкладки — отпускать,
на возврат+play — перезапрашивать. Отсутствие API — тихий no-op.

**Критерий приёмки.** Экран не гаснет во время эфира на поддерживающих
устройствах; тест на чистой обёртке жизненного цикла (play/pause/visibility).

### FR-8. Клавиатурная навигация и доступность списков (P2)

**Требование.** Список каналов управляется с клавиатуры: `↑`/`↓` — перемещение,
`Enter` — включить; фокус видим; модалки — фокус-ловушка с возвратом фокуса
на кнопку-инициатор; skip-link к основному содержимому.

**Критерий приёмки.** Полный обход интерфейса без мыши; расчёт соседей
фокуса — чистая функция с тестами.

### FR-9. Продолжение VOD/catchup с последней позиции (P2)

**Требование.** Для неэфирного контента (VOD/catchup, где есть seek) позиция
`currentTime` сохраняется per-канал (localStorage, TTL ~7 дней); при повторном
открытии — предложение продолжить с места, кнопка «С начала».

**Критерий приёмки.** Закрыл и открыл VOD — продолжается с ±5с сохранённой
позиции; для живого эфира позиция не сохраняется; хранение и восстановление —
чистые модули с тестами.

### FR-10. Локальный плейлист из файла (P3)

**Требование.** В менеджере можно добавить `.m3u` (и опционально EPG) файлом
с диска: содержимое хранится в OPFS, плейлист получает флаг «локальный» и
работает без сети. Не-http(s) URL-инварианты не трогаем — у локального
источника `playlistUrl` отсутствует/заменён маркером.

**Критерий приёмки.** Локальный плейлист: добавление, переключение,
избранное/недавние/поиск работают, файл не покидает устройство; перезагрузка
страницы восстанавливает его из OPFS; чистые модули чтения/записи OPFS
покрыты тестами (фейковый handle в node).

### FR-11. Экспорт избранного в `.m3u` (P3)

**Требование.** Кнопка «Экспорт избранного» собирает валидный M3U
(`#EXTM3U` + `#EXTINF` с `tvg-id`/`tvg-logo`/`group-title`) из избранных
каналов активного плейлиста и скачивает файл.

**Критерий приёмки.** Полученный файл парсится собственным `parseM3U` без
потерь каналов (тест кругового перехода); совместим со стандартными плеерами.

### FR-12. Диплинк на канал (P3)

**Требование.** `?ch=<url>` ищет канал по URL в активном плейлисте и включает
его после загрузки; канал не найден — тихий тост и обычный список.

**Критерий приёмки.** Ссылка с `?ch=` открывает канал; логика поиска/автоплея
— чистая функция с тестами; параметр не конфликтует с `?p=`.

### FR-13. Sleep-таймер (P3)

**Требование.** В меню плеера — «выключить через 30/60/90 мин / в конце
передачи»: по истечении — пауза + затемнение кадра; любое действие
пользователя отменяет затемнение. Таймер переживает смену канала.

**Критерий приёмки.** Выбор таймера виден (бейдж с остатком); «в конце
передачи» использует EPG-окончание текущей передачи; логика тика/отмены —
чистый модуль с тестами (фейковый таймер).

### FR-14. Скриншот кадра (P3)

**Требование.** Кнопка/клавиша сохраняет текущий кадр в PNG
(`drawImage(<video>)` + `toBlob`); для tainted-канваса (нативный cross-origin
без CORS) — честный тост «браузер не даёт снять кадр».

**Критерий приёмки.** HLS-канал даёт PNG с фактическим кадром; имя файла
содержит канал и время; невозможность захвата не роняет плеер.

### FR-15. Кросс-таб синхронизация настроек (P3)

**Требование.** Изменения плейлистов/избранного в другом табе подхватываются
через `storage`-событие без перезагрузки (мердж простым перечитыванием
состояния).

**Критерий приёмки.** Два таба: добавил плейлист в одном — во втором
появился без reload; конфликтов записи при одновременных правках не
возникает (last-write-wins объявлен в доках).

## Честный анализ: чего не хватает

Аудит кода после редизайна v2: сначала долги, которые уже видны в коде,
потом пробелы в заявленном, потом идеи.

### P1 — долги и заметные пробелы

1. **Экспорт/импорт не переносит «недавние».** Комментарий в `backup.ts`
   обещает recents, но в `Backup` поля нет — при переезде на новое устройство
   «Продолжить просмотр» теряется. Дополнить `Backup` опциональным `recents`
   (version остаётся 1, импорт принимает и старые файлы) + тест.
2. **Легаси-избранное не мигрирует.** До мультиплейлистов избранное жило
   в глобальном ключе `iptv-hub.favorites.v1`, теперь — в
   `iptv-hub.favorites.v1:<id>`; `migrateLegacy` переносит только конфиг.
   Апгрейд со старой версии молча теряет избранное.
3. **Гонка EPG при переключении плейлистов.** `openPlaylist` стреляет
   `loadEpg` без отмены: если быстро сменить плейлист, поздний ответ старой
   загрузки затрёт `epg` данными не того плейлиста. Нужен guard
   (проверка актуальности при resolve) или AbortController + тест на чистой
   логике.
4. **Версия пакета отстаёт**: `package.json` — 0.2.0, доки звали v0.2.3.
   VERSION в sw.js больше не вручную (штампуется хэшем сборки, PR#78),
   но `package.json` стоит бампить синхронно с релизами — тест/скрипт в CI,
   сверяющий версию пакета с доками.
5. **EPG в память целиком.** До 200MB распакованных парсится в память —
   гигантские файлы на слабых устройствах. Индексация по каналам при парсинге
   + переход на стриминговое чтение из IndexedDB, если подтвердится проблема.
6. **Ошибка без diagnostics при CORS-блокировке потока.** Плеер называет
   mixed content и HTTP-статусы, но «подозрение на CORS» — гадание по
   косвенным признакам; стоит один раз подтвердить через `fetch` HEAD и
   показать точную причину с чек-листом (как для плейлиста).

### P3 — платформа и идеи

18. **Плейлист из локального файла.** Сейчас источник — только URL. Дать
    добавить `.m3u`/EPG файлом: хранить содержимое в OPFS, плейлист получает
    флаг «локальный». Полностью приватно, файл не покидает устройство.
    Аккуратно: модель `Playlist` завязана на http(s)-URL.
19. **Экспорт избранного в `.m3u`** — получить плейлист из избранных каналов,
    совместимый с родительским пайплайном и любыми плеерами
    (`exportFavorites` в `favorites.ts` уже намекает на «поделиться»).
20. **Диплинк на канал** — `?ch=<url>`: открытие конкретного канала по
    ссылке (поиск по URL в активном плейлисте + автоплей). Удобно для
    закладок и «поделиться каналом».
21. **Sleep-таймер** — «выключить через 30/60 мин»: классика IPTV-плееров,
    чисто клиентская (пауза + затемнение).
22. **Скриншот кадра** — `drawImage(<video>)` → PNG. Через MSE кадр
    не «испачкан» и захватывается; у нативных cross-origin потоков без CORS
    канвас будет tainted — честно тостить «браузер не даёт».
23. **Кросс-таб синхронизация** — два таба редактируют один localStorage,
    не видя друг друга; слушать `storage`-событие для плейлистов/избранного.
24. **Напоминания о передаче** — «напомнить за 5 минут» из гайда. Пока
    открыта вкладка — обычный таймер; Notification API требует permission
    и остаётся под вопросом. Всё локально, без серверов.
25. **Кастомные эмодзи-пары из родительского `iptv`** (FNV-1a по URL) для
    визуального различения каналов — консистентность с пайплайном.
