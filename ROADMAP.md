## Где мы сейчас

Из MVP «парсер + список + HLS» вырос полноценный плеер с дизайн-системой v2:

- **Редизайн v2** (PR#74): токены, линейные иконки, четыре равноправных
  раздела (каналы / избранное / недавние / настройки) — таб-бар на телефоне,
  сайдбар на десктопе; полоса хода передачи с «К эфиру»; блок «Продолжить
  просмотр»; жесты на кадре (свайп — канал, двойной тап — ±15с)
- **Плейлисты**: несколько источников, менеджер с инлайн-редактором
  (без prompt), ленивая миграция со старого конфига, `?p=` апсертит,
  избранное per-плейлист, экспорт/импорт настроек (versioned JSON)
- **Плеер**: hls.js + нативный fallback, пауза/громкость/prev-next,
  PiP, перемотка ±15с (архив/VOD), выбор качества кнопкой с живым лейблом
  (Auto·FHD/HD/SD), аудио/субтитры кнопками с меню в теме сайта,
  нативный fullscreen с сохранением транспортных контролов,
  автовосстановление network/media ошибок + retry-кнопка ↻; при фатальной
  ошибке плеер называет её причину, а http-каналы на https-странице
  автоматически спасает апгрейдом на https-порт (PR#63, #68)
- **Запись эфира**: HLS пишется сегментами без перекодирования (PR#61),
  звук захватывается прямо с `<video>` (fallback — канвас без звука),
  сорвавшаяся запись не выдаётся за готовый файл (PR#60), тост-кнопка
  скачивания для Firefox/Zen
- **EPG**: сейчас/далее в списке, модалка-гайд с вкладками дней,
  catchup-архив до 3 дней (tvg-rec/catchup-source, {utc}/{lutc}/…)
- **UX**: тёмная/светлая темы (системный дефолт, без FOUC), PWA
  (оффлайн-shell + кэш плейлиста/EPG), горячие клавиши (space/←→/↑↓/M/J/L/F),
  поиск, категории, избранное, «недавно просмотренные» (10 чипов),
  виртуализированный список (~2600 каналов, в DOM только видимое окно;
  спейсер учитывает колонки сетки), мобильный портрет без наезда контролов —
  зоны плеер-бара в столбец, touch-цели ≥ 40px, safe-area, bottom-sheet гайд (PR#64),
  экранный лог по `?debug=1` для отладки на телефоне
- **Обновление данных**: PWA обновляется сама (версия SW штампуется хэшем
  сборки, вкладка перезагружается по контроллеру или тостом «Обновить»);
  плейлист перепроверяется по расписанию или кнопкой «Проверить сейчас»
  (сейчас/каналы/передачи — отчётом в колокольчик), EPG подтягивается
  из заголовка плейлиста и обновляется вместе с ним; неиграбельные
  http-каналы публичных хостов скрываются при разборе (приватные — остаются)
- **Центр уведомлений**: колокольчик в шапке с бейджем непрочитанных,
  история до 20 уведомлений в localStorage (скрытые http, итоги проверки)
- **Инфраструктура**: 313 юнит-тестов, CI (Node 22, actions v5) с required
  check `build`, branch protection на main, деплой Pages из main

## Честный анализ: чего не хватает

потом пробелы в заявленном, потом идеи.

### P1 — долги и заметные пробелы

1. ~~**Экспорт/импорт не переносит «недавние».**~~ — **сделано**: `Backup`
   получил опциональное `recents` (per-плейлист, version остаётся 1, старые
   файлы принимаются), импорт восстанавливает «Продолжить просмотр».
2. ~~**Легаси-избранное не мигрирует.**~~ — **сделано**: `migrateLegacy`
   переносит непустой глобальный `iptv-hub.favorites.v1` в
   `iptv-hub.favorites.v1:<id>` первого плейлиста (если своего ещё нет;
   легаси-ключ сохраняется).
3. ~~**Гонка EPG при переключении плейлистов.**~~ — **сделано**: `LatestGuard`
   (`src/latest.ts`) — генерации при загрузке; неактуальный ответ (плейлист
   сменили, пришёл поздний ответ) не применяется, ни в `openPlaylist`, ни
   при периодической проверке.
4. ~~**Версия пакета отстаёт**~~ — **сделано**: `package.json` бампнут до
   0.2.5, `tests/version.test.ts` сверяет версию со статусом в AGENTS.md и
   ROADMAP.md (гоняется в CI, расхождение краснит PR).
5. **EPG в память целиком.** До 200MB распакованных парсится в память —
   гигантские файлы на слабых устройствах. Индексация по каналам при парсинге
   + переход на стриминговое чтение из IndexedDB, если подтвердится проблема.
6. ~~**Ошибка без diagnostics при CORS-блокировке потока.**~~ — **сделано**:
   при фатальной ошибке плеер один раз пробует поток обычным `fetch`
   (`src/stream-diagnostics.ts`) и пишет вердикт с чек-листом в колокольчик:
   CORS есть / HTTP-статус / CORS нет или недоступен.

### P3 — платформа и идеи

18. **Плейлист из локального файла.** Сейчас источник — только URL. Дать
    добавить `.m3u`/EPG файлом: хранить содержимое в OPFS, плейлист получает
    флаг «локальный». Полностью приватно, файл не покидает устройство.
    Аккуратно: модель `Playlist` завязана на http(s)-URL.
19. **Экспорт избранного в `.m3u`** — получить плейлист из избранных каналов,
    совместимый с родительским пайплайном и любыми плеерами
    (`exportFavorites` в `favorites.ts` уже намекает на «поделиться»).
20. **Диплинк на канал** — `?ch=<url>`: открытие конкретного канала по
    ссылке (поиск по URL в активном плейлисте + автоплей). Удобно для
    закладок и «поделиться каналом».
21. **Sleep-таймер** — «выключить через 30/60 мин»: классика IPTV-плееров,
    чисто клиентская (пауза + затемнение).
22. **Скриншот кадра** — `drawImage(<video>)` → PNG. Через MSE кадр
    не «испачкан» и захватывается; у нативных cross-origin потоков без CORS
    канвас будет tainted — честно тостить «браузер не даёт».
23. **Кросс-таб синхронизация** — два таба редактируют один localStorage,
    не видя друг друга; слушать `storage`-событие для плейлистов/избранного.
24. **Напоминания о передаче** — «напомнить за 5 минут» из гайда. Пока
    открыта вкладка — обычный таймер; Notification API требует permission
    и остаётся под вопросом. Всё локально, без серверов.
25. **Кастомные эмодзи-пары из родительского `iptv`** (FNV-1a по URL) для
    визуального различения каналов — консистентность с пайплайном.
26. **Android TV-компаньон** (Kotlin + WebView на этот же сайт, D-pad-карта
    клавиш). Сайт уже mobile-first, но focus-стили под D-pad надо доделать (см. 10).
27. **DASH-адаптер** (dash.js) за проверкой формата — редкие провайдеры.
28. **Share-target** в PWA-манифесте: «поделиться» ссылкой на плейлист из
    другого приложения прямо в IPTV Hub (`?p=`-upsert уже готов принять её —
    остался манифест + обработка share).
29. ~~Фильтр «скрыть каналы с http»~~ — **сделано** иначе, чем задумано:
    не настройка per-плейлист, а автоматическое скрытие неиграбельных
    http-каналов публичных хостов при разборе (PR#80); приватные хосты
    (домашние IPTV) остаются.
30. **Отложенное**: мульти-audio в PiP (платформенное ограничение),
    Media Sessions для кнопок гарнитуры — проверить объём работы.

## Не делать (осознанные решения, см. AGENTS.md)

- Серверный прокси/бэкенд — ломает модель статики.
- Кэширование медиа-сегментов — живой ТВ в оффлайне не существует.
- Сторонние UI-кит и аналитика — privacy-first, bundle уже 190KB gzip
  из-за hls.js; новые runtime-зависимости — только через обсуждение.

## Практика выпуска

- VERSION в `public/sw.js` штампуется хэшем сборки автоматически (PR#78);
  остаётся бампить `package.json` при релизах (см. P1-4).
- Каждое изменение — через issue → ветку → PR → зелёный `build` → merge.
- Перед merge: `npm test` + `npm run build` локально зелёные.
- В доках не фиксировать точное число тестов — врёт быстрее кода;
  «313» — снимок на дату актуализации, общий счётчик живёт в CI.
