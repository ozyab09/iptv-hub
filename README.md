# 📺 IPTV Hub

Self-hosted веб-плеер для ваших IPTV-плейлистов с телепрограммой. Статика на
GitHub Pages, бэкенда нет: плейлист и EPG скачиваются браузером напрямую
из вашего S3-бакета (Yandex Object Storage и любой S3-совместимый).

Парный проект: [iptv](https://github.com/ozyab09/iptv) — пайплайн, который
фильтрует M3U + EPG и кладёт их в S3 по расписанию.

## Возможности

- 📋 Несколько плейлистов: добавление/редактирование/удаление, переключение
  в шапке; избранное и «недавно просмотренные» — у каждого свои
- 🔎 Категории + поиск по названию канала
- 📅 «Сейчас / далее» из EPG (XMLTV, `.xml` и `.xml.gz`) и полная программа
  передач по дням; **catchup-архив** — смотреть прошедшие передачи до 3 дней
  назад (если провайдер даёт `tvg-rec`/`catchup`)
- 🎬 HLS (`hls.js`) + нативные форматы (Safari/iOS); выбор качества,
  аудиодорожки и субтитров; PiP; перемотка ±15с; retry при сбоях
- ⏺ **Запись эфира**: HLS — сегментами без перекодирования (родное качество,
  `.ts`/`.mp4`), остальное — перекодированием в `.webm`
- 🌗 Тёмная и светлая темы (по системной, переключаются вручную)
- ⌨️ Горячие клавиши: `Space` — пауза, `←`/`→` — канал, `↑`/`↓` — громкость,
  `M` — звук, `J`/`L` — ±15с, `F` — полный экран (работает и в ru-раскладке:
  `ь`, `о`, `д`, `а`)
- 🐞 Экранный лог для отладки на телефоне: добавьте `?debug=1` к адресу
- 📱 Мобильный first, **PWA**: установка на домашний экран, оффлайн-оболочка,
  последняя копия плейлиста/EPG доступна без сети
- 🔒 Privacy-first: никаких аналитики/бэкенда, ссылки хранятся в `localStorage`;
  все настройки переносятся экспортом/импортом JSON
- 🎛 Четыре раздела: каналы, избранное, недавние, настройки — таб-бар на
  телефоне, сайдбар на десктопе
- ▶️ Контролы поверх кадра с автоскрытием, полоса хода передачи и «К эфиру»
- 👆 Жесты на телефоне: свайп по кадру — канал, двойной тап у края — ±15 с

## Конфигурация источника

Плейлистов может быть несколько — все способы ниже пополняют и переключают
общий список (хранится в localStorage, никуда больше не отправляется):

1. **GET-параметры** — даёте браузеру ссылку вида:

   ```
   https://ozyab09.github.io/iptv-hub/?p=<URL-плейлиста>&e=<URL-EPG>
   ```

   Оба значения должны быть валидными http(s)-URL (encodeURIComponent).
   Такая ссылка делает **upsert**: если плейлист с этим URL уже в списке —
   он активируется (переданный `e=` обновит его EPG), иначе — добавляется
   с именем «Плейлист» и сразу открывается. EPG можно опустить (`?p=...`),
   тогда если в `#EXTM3U` есть `tvg-url`/`url-tvg`, EPG возьмётся оттуда.

2. **Менеджер плейлистов** (кнопка 📃 в шапке) — добавьте источник по
   URL с именем, отредактируйте или удалите; там же экспорт/импорт всех
   настроек в JSON и кнопка «Вернуться к просмотру».

3. **Переключатель в шапке** (📺) — быстрое переключение между уже
   добавленными плейлистами.

Старый одиночный конфиг (до мультиплейлистов) переносится в список
автоматически при первом открытии. Для отладки доступен `?debug=1` —
экранный лог вместо консоли (удобно на телефоне).

## CORS на S3-бакете (обязательно)

Статика на `*.github.io`, файлы на другом домене — без CORS браузер не даст
их прочитать. Для Yandex Object Storage: бакет → **Settings → CORS** → PUT:

```xml
<CORSConfiguration>
  <CORSRule>
    <AllowedOrigin>https://ozyab09.github.io</AllowedOrigin>
    <AllowedOrigin>http://localhost:5173</AllowedOrigin>
    <AllowedOrigin>http://localhost:4173</AllowedOrigin>
    <AllowedMethod>GET</AllowedMethod>
    <AllowedHeader>*</AllowedHeader>
    <MaxAgeSeconds>3600</MaxAgeSeconds>
  </CORSRule>
</CORSConfiguration>
```

Для локальной разработки удобнее `http://localhost:*`, но Yandex может не
принять wildcard в origin — добавьте конкретные порты.

> ⚠️ **Про сами потоки:** CORS-политика бакета разрешает скачивание
> *плейлиста и EPG*, но не влияет на доступность медиа-потоков из чужих CDN.
> HLS через `hls.js` обычно работает (fetch + MSE), а Safari/iOS играет
> нативно, минуя CORS-ограничения. Потоки без CORS в Chrome могут не играть —
> это ограничение браузера, а не баг плеера. См. «Ожидания» в AGENTS.md.

## Смешанный контент: почему http-каналы не играют

Сайт живёт на GitHub Pages и открывается **только по `https://`**. Браузеры
(Chrome, Firefox, Safari) блокируют загрузку http-контента с https-страницы —
это называется *mixed content* (смешанный контент). Иначе шифрование и
замок 🔒 в адресной строке не значили бы ничего: любой в публичном Wi-Fi или
у провайдера мог бы подменить то, что страница загружает открытым текстом.

Заблокированный запрос даже не уходит в сеть — снаружи это выглядит как
обычный «сбой сети», что сбивает с толку.

**Что делает плеер:**

- при клике на http-канал с https-страницы **сразу пробует тот же поток
  по `https://`** (порт 443 того же хоста) — у большинства IPTV-CDN он
  отвечает, и канал играет (тост: «пробую https…»);
- если по https поток не отвечает — сообщает прямо: «Поток недоступен
  и по https — у провайдера, похоже, нет TLS», без бесконечных
  переподключений; работает retry-кнопка ↻;
- http-каналы с публичных хостов **скрываются из списка** ещё при разборе
  плейлиста: играть они на https-странице не могут в принципе. После
  загрузки показывается тост «Скрыто N каналов по http://…», чтобы пропажа
  не выглядела потерей части плейлиста;
- локальные и приватные адреса (`localhost`, `10.*`, `192.168.*`,
  `172.16–31.*`, `.local`) не апгрейдятся и из списка **не скрываются** —
  у таких хостов TLS на 443 обычно не поднят, зато mixed content на них
  не действует, и домашние IPTV-серверы играют.

**Чек-лист, чтобы каналы играли:**

1. Ссылка на плейлист (M3U) и EPG — **https** (для S3 это endpoint бакета
   `https://<bucket>.storage.yandexcloud.net/…`). Http-плейлист загрузить
   можно, но браузер может заблокировать его той же политикой.
2. Потоки внутри плейлиста по возможности тоже **https**. Родительский
   пайплайн [iptv](https://github.com/ozyab09/iptv) оставляет http-ссылки
   как есть — если провайдер даёт https-вариант, фильтруйте и меняйте
   на своей стороне.
3. Http-каналы публичных хостов в списке не видны — приложение их скрывает
   (см. выше). Http-канал с приватного адреса останется в списке и сыграет
   только с http-страницы или с доверенного origin (localhost); обход через
   свой прокси невозможен по принципам проекта (zero backend, см. AGENTS.md).

**Исключение:** локальная разработка. `http://localhost:5173` (`npm run dev`)
и `http://localhost:4173` (`npm run preview`) — доверенные origin, браузер
разрешает им http-запросы, так что на локальной машине http-каналы играют.

## Запись эфира

Кнопка ⏺ в плеер-баре: старт записи, повторный клик — сохранение. Файл
`Канал_ГГГГ-ММ-ДД_ЧЧ-ММ.<ext>` кладётся в папку загрузок **без диалогов**.

**HLS-каналы пишутся сегментами** — теми самыми, что плеер и так скачивает.
Ничего не перекодируется: оригинальное качество, родной звук, нулевая нагрузка
на процессор, файл `.ts` (или `.mp4` для fragmented MP4), который открывают
и VLC, и системные плееры. Работает во всех браузерах, включая Firefox для
Android.

Сегменты уходят на диск через OPFS по мере прихода, поэтому длинная запись не
съедает память; если OPFS недоступен, копятся в памяти. Потолок — 1 ГБ, дальше
запись сохраняется сама.

Запись начинается с границы текущего сегмента — погрешность до нескольких
секунд. Если качество стоит на Auto и плеер переключит уровень посреди записи,
в файле окажутся куски разного разрешения.

**Остальное** (нативное воспроизведение, прямые mp4) пишется перекодированием
в `.webm`: захват прямо с `<video>`, а где он не работает — картинка с канваса
и звук через Web Audio. Каким путём пошла запись, приложение сообщает тостом —
на телефоне консоли нет.

Запасной путь требует, чтобы вкладка оставалась на переднем плане: кадры
снимаются по `requestAnimationFrame`, а он не тикает в фоне.

Записывается то, что слышно: если плеер замьючен, файл получится тихим. Звука
не будет и у каналов, которые играют напрямую (не через hls.js) с чужого домена
без CORS — Web Audio по стандарту отдаёт в этом случае тишину.

> ⚠️ **Перекодирование на Firefox для Android не работает.** Захват `<video>`
> там отдаёт живые дорожки, но энкодер падает с `UnknownError` через секунду,
> а `drawImage` на канвас рисует черноту: декодированное видео лежит в
> аппаратной поверхности, недоступной канвасу. Звук при этом пишется, поэтому
> без проверки получался бы файл с чёрным экраном — приложение распознаёт это
> и останавливает запись с явным сообщением. HLS-каналов это не касается: они
> пишутся сегментами, минуя и канвас, и энкодер.

Если браузер при каждом скачивании спрашивает «Куда сохранить?» — это его
настройка, отключается так:
- **Chrome/Edge**: Настройки → Загрузки → выключить «Перед загрузкой спрашивать,
  куда сохранять файлы»
- **Firefox**: Настройки → Основные → Загрузки → «Всегда спрашивать, где сохранять
  файлы» — снять галочку

## PWA

- **Установка:** Chrome/Android — «Установить приложение» в меню; iOS Safari —
  «На экран «Домой»». Запускается в standalone-режиме без адресной строки.
- **Иконки:** генерируются скриптом `npm run icons` (без внешних зависимостей,
  PNG собирается вручную через `node:zlib`) → `public/icons/`.
- **Оффлайн:** оболочка (HTML/CSS/JS/иконки) кешируется cache-first; плейлист
  и EPG — network-first с отдачей последней успешной копии без сети.
  Живые медиа-потоки **не кешируются** — это осознанное решение.
- **Обновления:** кэши версионированы (`v0.2.3` в `public/sw.js`); при выпуске
  новой версии bump'ните `VERSION` в sw.js — старые кэши удалятся в `activate`.
  Новая SW-версия подхватывается после перезагрузки страницы.
