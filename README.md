# 📺 IPTV Hub

Self-hosted веб-плеер для ваших IPTV-плейлистов с телепрограммой. Статика на
GitHub Pages, бэкенда нет: плейлист и EPG скачиваются браузером напрямую
из вашего S3-бакета (Yandex Object Storage и любой S3-совместимый).

Парный проект: [iptv](https://github.com/ozyab09/iptv) — пайплайн, который
фильтрует M3U + EPG и кладёт их в S3 по расписанию.

[![CI + Pages](https://github.com/ozyab09/iptv-hub/actions/workflows/ci.yml/badge.svg)](https://github.com/ozyab09/iptv-hub/actions/workflows/ci.yml)

## Возможности

- 📋 Несколько плейлистов: добавление/редактирование/удаление, переключение
  в шапке; избранное и «недавно просмотренные» — у каждого свои
- **Свои имена и скрытие каналов** — кнопка редактирования у канала или
  правый клик открывают имя и переключатель скрытия. Пустое имя возвращает
  исходное. Алиас отображается в списках, поиске, программе и плеере;
  сопоставление EPG сохраняется. Скрытые каналы пропадают из списка,
  избранного, недавних и поиска, но доступны по ссылке с `?ch=<URL потока>`.
  Изменения хранятся локально для каждого плейлиста и переживают обновление
  источника. В настройках можно сбросить имена и скрытие текущего плейлиста,
  сохранив избранное. Эти изменения пока не входят в резервную копию JSON.
- 🔎 Категории + поиск по названию канала и передачам EPG. Поиск передач
  работает без учёта регистра, пунктуации и лишних пробелов: «что где когда»
  находит «Что? Где? Когда?». Исходное название передачи сохраняется.
  Результаты показывают канал, название, дату и время; нажатие включает доступный архив
  прошедшей передачи или эфир канала. Без EPG поиск каналов работает как раньше.
  В результатах передач показан логотип канала; без изображения или при
  ошибке его загрузки — монограмма, как в обычном списке.
  **Мини-превью**: наведите курсор
  на канал (на телефоне — удержите палец) — тост покажет, что сейчас в эфире,
  не включая канал
  Переключение каналов сохраняет прокрутку списка, включая колонку логотипов;
  смена поиска, категории или раздела возвращает список к началу.
  Меню категорий при просмотре использует шрифт и цвета текущей темы;
  длинные названия переносятся отдельно от счётчиков, большой список прокручивается.
- 📅 «Сейчас / далее» из EPG (XMLTV, `.xml` и `.xml.gz`) и полная программа
  передач по дням; **catchup-архив** — смотреть прошедшие передачи до 3 дней
  назад (если провайдер даёт `tvg-rec`/`catchup`)
- 🎬 HLS (`hls.js`) + нативные форматы (Safari/iOS); выбор качества,
  аудиодорожки и субтитров; PiP; перемотка ±15с; retry при сбоях
  Кнопка `Auto` открывает доступные варианты качества HLS. Выбор закрывает
  меню; закрыть его также можно повторным нажатием, кликом вне меню, Escape или «Назад».
- **Мульти-вью 2×2** — кнопка сетки на кадре открывает до четырёх каналов
  одновременно на десктопе (ширина окна от 1024 px). Выберите окно, затем
  канал в списке; звук идёт только из выбранного окна. Пауза, громкость
  и перемотка управляют выбранным окном. «Один канал» возвращает его
  в обычный плеер, закрывая остальные потоки. При сужении окна сетка
  закрывается автоматически; на телефоне кнопка объясняет ограничение.
  Четыре потока увеличивают расход трафика, нагрузку и расход батареи.
  Для записи, выбора качества и дорожек вернитесь в одиночный режим;
  вход в сетку завершает текущую запись.
- ⏺ **Запись эфира**: HLS — сегментами без перекодирования (родное качество,
  `.ts`/`.mp4`), остальное — перекодированием в `.webm`
- 🌗 Тёмная и светлая темы (по системной, переключаются вручную)
  Логотипы каналов в списке, поиске и «Продолжить просмотр» имеют нейтральную
  подложку: белые и тёмные детали читаются в обеих темах, цвета изображения сохраняются.
- **Язык интерфейса ru/en** — в настройках, без перезагрузки. При первом запуске
  выбирается по языку браузера (русский для `ru`, английский для остальных),
  ручной выбор сохраняется на устройстве. Переведены настройки, менеджер плейлистов,
  навигация, колокольчик и основные ошибки загрузки/воспроизведения.
  Названия каналов, плейлистов и тексты EPG сохраняются дословно; остальные
  элементы плеера и программы пока на русском. Незавершённый ввод при смене языка сохраняется.
- ⌨️ Горячие клавиши: `Space` — пауза, `←`/`→` — канал, `↑`/`↓` — громкость,
  `M` — звук, `J`/`L` — ±15с, `F` — полный экран, `C` — свернуть/вернуть
  список (в ru-раскладке тоже); в списке каналов `↑`/`↓` — перемещение,
  `Home`/`End` — края, `Enter` — включить, `/` — поиск, из поиска `↓` — в список
- 🖥 **Скрыть панель целиком** — рядом со сворачиванием списка: кнопка
  «×» в шапке списка убирает и навигацию, и список каналов, оставляя
  только видео на весь экран; вернуть — кнопка на кадре, `C` или выбор
  канала свайпом. Выбор запоминается
  В свёрнутой колонке логотипов кнопки раскрытия и скрытия расположены
  друг под другом и помещаются внутри панели.
  При полном скрытии панели кнопка возврата остаётся видимой в левом верхнем
  углу видео, даже когда остальные контролы исчезают.
- 🐞 Экранный лог для отладки на телефоне: добавьте `?debug=1` к адресу
- 📸 **Скриншот кадра** — кнопка камеры в шапке кадра или клавиша `S`:
  PNG с именем канала и временем. У нативных cross-origin потоков без
  CORS браузер не даёт захватить кадр — приложение честно сообщит
- 🤖 **CI проверяет вёрстку**: Playwright (chromium) против продакшен-сборки —
  мобильный портрет/пейзаж и десктоп, горизонтальные наезды; локально:
  `npm run build && npm run test:visual`
- 📱 Мобильный first, **PWA**: установка на домашний экран, оффлайн-оболочка,
  последняя копия плейлиста/EPG доступна без сети
- 🔒 Privacy-first: никаких аналитики/бэкенда, ссылки хранятся в `localStorage`;
  все настройки переносятся экспортом/импортом JSON
- 🪟 Кросс-таб синхронизация: открытые вкладки видят изменения плейлистов,
  избранного и темы друг друга без перезагрузки (last-write-wins) — включая «недавние»
  каналы каждого плейлиста, «Продолжить просмотр» переживёт переезд
- 🎛 Четыре раздела: каналы, избранное, недавние, настройки — таб-бар на
  телефоне, сайдбар на десктопе
  Настройки во время просмотра остаются полноценной панелью: клавиша `C`
  сворачивает только список каналов. Переключатели темы и обновления
  подстраиваются под ширину панели; выбранный вид списка сохраняется
  при переходе в настройки и обратно.
- ▶️ Транспортная дека в один ряд — ±15с, соседние каналы, пауза, запись
  (см. «Управление»); автоскрытие контролов, полоса хода передачи и «К эфиру»
- 🔔 **Центр уведомлений** — колокольчик в правом углу шапки: скрытые
  http-каналы, результаты проверки плейлиста (см. «Уведомления»)
- 🔄 **Периодическое обновление плейлиста** — по расписанию или кнопкой
  «Проверить сейчас», с отчётом в колокольчик; EPG подтягивается из
  заголовка плейлиста и обновляется вместе с ним (см. «Обновление плейлиста»).
  Если интервал включён, возврат в приложение после долгого фона проверяет
  плейлист сразу, не дожидаясь таймера
- 👆 Жесты на телефоне: свайп по кадру — канал, двойной тап у края — ±15 с
- ⏯ **Продолжение с места** — позиция VOD/catchup запоминается (7 дней)
  и при повторном открытии канал продолжается с неё; живой эфир не
  запоминается
- ⏻ **Sleep-таймер** — кнопка с часами в транспортной деке: выключить
  через 30/60/90 минут или в конце передачи (по EPG); по истечении — пауза
  и затемнение кадра, любое касание возвращает картинку

## Зеркала каналов

Записи M3U с одинаковым непустым `tvg-id` объединяются в один канал. Первый
адрес и его имя, категория и логотип остаются основными; следующие адреса
используются как зеркала в порядке файла. Без `tvg-id` одноимённые каналы
остаются отдельными. Также можно указать зеркала в одной строке URL:

```m3u
#EXTINF:-1 tvg-id="news",Новости
https://first.example/live.m3u8 | https://second.example/live.m3u8
```

При фатальной ошибке плеер автоматически пробует следующий адрес без сообщения
об ошибке первого. Когда зеркала закончились, действует обычная обработка ошибки
и кнопка повтора; ручной повтор начинает с основного адреса. Избранное, недавние
и настройки канала привязаны к основному URL. Ссылка `?ch=` на зеркало тоже
открывает этот канал; PIN проверяется как обычно. Архив catchup не подменяется
зеркалами эфира. Сегментная запись при смене зеркала останавливается и сохраняется,
чтобы не смешивать сегменты разных источников. Публичные HTTP-адреса по-прежнему
отфильтровываются; наличие зеркал не отменяет требования CORS и HTTPS.

## Родительский PIN

В настройках выберите группу активного плейлиста и установите PIN из 4–8 цифр
с повторным вводом. PIN нужен при входе в эту группу и каждом запуске её канала,
включая избранное, недавние, поиск передач, catchup-архив, переключение соседних
каналов, мульти-вью и ссылку `?ch=`. Неверный PIN и отмена не запускают канал.
Установка защиты останавливает уже открытый канал группы; изменение PIN-настроек
в другой вкладке останавливает её просмотр. Для снятия защиты нужен текущий PIN.

Хранится хеш PBKDF2 с отдельной случайной солью, раздельно для каждого плейлиста.
PIN-настройки не включены в JSON резервной копии; сброс имён каналов их не удаляет.
Если PIN забыт, очистите **все данные сайта** в настройках браузера: это также
удалит плейлисты, избранное и остальные локальные настройки. Это локальное
ограничение интерфейса, которое можно обойти очисткой или изменением данных
браузера; серверной проверки доступа нет.

## Конфигурация источника

### Настройки плеера

В разделе «Настройки → Плеер» можно задать целевой буфер HLS (5–600 секунд,
по умолчанию 30), включить низкую задержку (по умолчанию выключена) и выбрать
таймаут диагностики недоступного потока (1–60 секунд, по умолчанию 8).
Нажмите «Сохранить»: изменения применятся при следующем запуске канала,
текущий поток и его повтор сохранят прежние значения. «По умолчанию» сбрасывает
эти три параметра. Настройки хранятся только в этом браузере и пока не входят
в резервную копию JSON.

Числовые поля и переключатель низкой задержки оформлены в цветах текущей темы.
`Tab` переводит фокус между ними, `Space` переключает низкую задержку, а стрелки
вверх/вниз меняют число в активном поле. Фокус виден и в светлой, и в тёмной теме.

Больший буфер требует больше памяти. Для живого HLS через hls.js доступен
**timeshift**: на паузе и после перемотки плеер продолжает скачивать сегменты,
расширяя буфер вперёд до 10 минут. После продолжения позиция сохраняется;
кнопки ±15 секунд и двойной тап перематывают только загруженные участки.
«К эфиру» возвращает к живой позиции, возобновляет просмотр и восстанавливает
обычный целевой буфер. Позади текущей позиции хранится до 10 минут эфира.
Смена канала, повтор или закрытие плеера сбрасывают timeshift. Это буфер в
памяти, а не запись: доступное окно зависит от памяти браузера и потока;
долгая пауза, потеря сети или выгрузка вкладки могут прервать продолжение.
Режим низкой задержки полезен для поддерживающих его HLS-потоков. Буфер и
низкая задержка применяются к hls.js; нативное воспроизведение Safari/iOS
управляет буфером самостоятельно.

### Плейлисты

Плейлистов может быть несколько — все способы ниже пополняют и переключают
общий список (хранится в localStorage, никуда больше не отправляется):

1. **GET-параметры** — даёте браузеру ссылку вида:

   ```
   https://ozyab09.github.io/iptv-hub/?p=<URL-плейлиста>&e=<URL-EPG>
   ```

   Оба значения должны быть валидными http(s)-URL (encodeURIComponent).
   Такая ссылка делает **upsert**: если плейлист с этим URL уже в списке —
   он активируется (переданный `e=` обновит его EPG), иначе — добавляется
   с именем «Плейлист» и сразу открывается. EPG можно опустить (`?p=...`),
   тогда если в `#EXTM3U` есть `tvg-url`/`url-tvg`, EPG возьмётся оттуда.

**Диплинк на канал:** `?ch=<URL-канала>` — открывает конкретный канал
из активного плейлиста (поиск по точному URL) и включает его. Работает
вместе с `?p=`/`?e=`: `?p=…&ch=…` сначала настроит плейлист, потом включит
канал. Канал не найден — приложение покажет список как обычно.

2. **Менеджер плейлистов** (кнопка 📃 в шапке) — добавьте источник по
   URL с именем, отредактируйте или удалите; там же экспорт/импорт всех
   настроек в JSON (плейлисты, избранное, тема и «недавние» каналы) и кнопка
   «Вернуться к просмотру». Быстрое переключение плейлистов не смешивает
   телепрограммы: поздний ответ старой загрузки EPG отбрасывается.

**Локальный плейлист файлом:** в форме добавления можно выбрать `.m3u` или `.m3u8`
с устройства — содержимое сохранится в приватное хранилище браузера
(OPFS) и никуда не отправится. Такой плейлист работает без сети,
у него есть избранное, недавние и поиск, как у сетевого.
Кнопка выбора файла оформлена как остальные действия настроек. `Tab` выделяет
её заметным фокусом, `Enter` открывает системный диалог выбора файла.
Список каналов доступен после перезагрузки без повторного выбора файла и без
сети (для просмотра эфира сеть нужна). Ранее импортированные источники
восстанавливаются, если файл ещё хранится в браузере. Удаление локального
плейлиста из менеджера также удаляет его файл и локальную телепрограмму.

3. **Переключатель в шапке** (📺) — быстрое переключение между уже
   добавленными плейлистами.

Старый одиночный конфиг (до мультиплейлистов) переносится в список
автоматически при первом открытии. Для отладки доступен `?debug=1` —
экранный лог вместо консоли (удобно на телефоне).

## CORS на S3-бакете (обязательно)

Статика на `*.github.io`, файлы на другом домене — без CORS браузер не даст
их прочитать. Для Yandex Object Storage: бакет → **Settings → CORS** → PUT:

```xml
<CORSConfiguration>
  <CORSRule>
    <AllowedOrigin>https://ozyab09.github.io</AllowedOrigin>
    <AllowedOrigin>http://localhost:5173</AllowedOrigin>
    <AllowedOrigin>http://localhost:4173</AllowedOrigin>
    <AllowedMethod>GET</AllowedMethod>
    <AllowedHeader>*</AllowedHeader>
    <MaxAgeSeconds>3600</MaxAgeSeconds>
  </CORSRule>
</CORSConfiguration>
```

Для локальной разработки удобнее `http://localhost:*`, но Yandex может не
принять wildcard в origin — добавьте конкретные порты.

> ⚠️ **Про сами потоки:** CORS-политика бакета разрешает скачивание
> *плейлиста и EPG*, но не влияет на доступность медиа-потоков из чужих CDN.
> HLS через `hls.js` обычно работает (fetch + MSE), а Safari/iOS играет
> нативно, минуя CORS-ограничения. Потоки без CORS в Chrome могут не играть —
> это ограничение браузера, а не баг плеера. См. «Ожидания» в AGENTS.md.
>
> Если канал всё же не заиграл, при фатальной ошибке плеер один раз
> пробует источник напрямую и пишет вердикт в колокольчик: «сервер отдал
> поток с CORS», «сервер ответил 403/404/…» или «CORS-заголовков нет /
> источник недоступен» — с чек-листом дальнейших шагов.

## Смешанный контент: почему http-каналы не играют

Сайт живёт на GitHub Pages и открывается **только по `https://`**. Браузеры
(Chrome, Firefox, Safari) блокируют загрузку http-контента с https-страницы —
это называется *mixed content* (смешанный контент). Иначе шифрование и
замок 🔒 в адресной строке не значили бы ничего: любой в публичном Wi-Fi или
у провайдера мог бы подменить то, что страница загружает открытым текстом.

Заблокированный запрос даже не уходит в сеть — снаружи это выглядит как
обычный «сбой сети», что сбивает с толку.

**Что делает плеер:**

- при клике на http-канал с https-страницы **сразу пробует тот же поток
  по `https://`** (порт 443 того же хоста) — у большинства IPTV-CDN он
  отвечает, и канал играет (тост: «пробую https…»);
- если по https поток не отвечает — сообщает прямо: «Поток недоступен
  и по https — у провайдера, похоже, нет TLS», без бесконечных
  переподключений; работает retry-кнопка ↻;
- http-каналы с публичных хостов **скрываются из списка** ещё при разборе
  плейлиста: играть они на https-странице не могут в принципе. После
  загрузки показывается тост «Скрыто N каналов по http://…», чтобы пропажа
  не выглядела потерей части плейлиста;
- локальные и приватные адреса (`localhost`, `10.*`, `192.168.*`,
  `172.16–31.*`, `.local`) не апгрейдятся и из списка **не скрываются** —
  у таких хостов TLS на 443 обычно не поднят, зато mixed content на них
  не действует, и домашние IPTV-серверы играют.

**Чек-лист, чтобы каналы играли:**

1. Ссылка на плейлист (M3U) и EPG — **https** (для S3 это endpoint бакета
   `https://<bucket>.storage.yandexcloud.net/…`). Http-плейлист загрузить
   можно, но браузер может заблокировать его той же политикой.
2. Потоки внутри плейлиста по возможности тоже **https**. Родительский
   пайплайн [iptv](https://github.com/ozyab09/iptv) оставляет http-ссылки
   как есть — если провайдер даёт https-вариант, фильтруйте и меняйте
   на своей стороне.
3. Http-каналы публичных хостов в списке не видны — приложение их скрывает
   (см. выше). Http-канал с приватного адреса останется в списке и сыграет
   только с http-страницы или с доверенного origin (localhost); обход через
   свой прокси невозможен по принципам проекта (zero backend, см. AGENTS.md).

**Исключение:** локальная разработка. `http://localhost:5173` (`npm run dev`)
и `http://localhost:4173` (`npm run preview`) — доверенные origin, браузер
разрешает им http-запросы, так что на локальной машине http-каналы играют.

`Settings → Pages → Source: GitHub Actions`. Workflow `ci.yml` сам тестирует,

## Уведомления: колокольчик

В правом углу шапки, рядом с кнопкой темы, — колокольчик. Он копит
уведомления о том, что произошло с плейлистами:

- **скрытые http-каналы** — сколько каналов не попало в список и почему
  (показывается один раз на плейлист);
- **результат проверки плейлиста** — что изменилось в списке каналов
  (см. следующий раздел).

Непрочитанные помечены цветной точкой-бейджем с числом. Клик по
колокольчику открывает список (текст + время), и всё увиденное считается
прочитанным — бейдж гаснет. «Очистить» стирает историю, клик мимо панели —
закрывает её. Хранится до 20 последних уведомлений в localStorage —
история переживает перезагрузку страницы.

## Обновление плейлиста

Список каналов хранится в localStorage, но провайдер меняет плейлист:
появляются новые каналы, закрываются старые. Чтобы список не каменел,
приложение умеет перепроверять источник:

- **Настройки → «Обновление плейлиста»** — выберите периодичность:
  выключено (по умолчанию), каждый час, раз в 6 часов или раз в сутки.
- **«Проверить сейчас»** — ручная проверка, не дожидаясь расписания.

Отчёт приходит в колокольчик: «Плейлист обновлён: +3, −1» или
«Плейлист проверён: без изменений» — и всегда с итогом: «Каналов: 1371,
передач: 22400». Если в обновлённом плейлисте стало больше скрытых
http-каналов — об этом тоже скажет уведомление.

Телепрограмма обновляется при каждой проверке — расписание передач
меняется чаще самого плейлиста. Если у плейлиста не указан EPG, но в его
заголовке есть ссылка (`tvg-url`), приложение подставит её в свойства
плейлиста автоматически; явно заданную ссылку оно не трогает. При
изменениях перечитываются категории, список и программа; сбой сети при
плановой проверке — тихий (ручная сообщит тостом).

Проверка — прямой запрос к источнику из браузера: бэкенда в проекте нет,
ссылка плейлиста по-прежнему никуда не отправляется.

## Управление: транспортная дека

Все кнопки воспроизведения собраны в один ряд — как на старом
аудиомагнитофоне, по ходу ленты. У каждой кнопки — hover-подсказка
с действием и горячей клавишей, порядок ряда читается по подсказкам:

| Кнопка | Что делает | Подсказка (title) |
| ------ | ---------- | ----------------- |
| ◀◀ | назад на 15 сек внутри передачи | «Назад 15 сек (J)» |
| ◀ | предыдущий канал | «Предыдущий канал (←)» |
| ⏸ / ▶ | пауза / продолжить — крупная кнопка в центре деки | «Пауза / продолжить (Space)» |
| ▶ | следующий канал | «Следующий канал (→)» |
| ▶▶ | вперёд на 15 сек | «Вперёд 15 сек (L)» |
| ⏺ | записать эфир в файл | «Записать эфир в файл» |

Логика порядка — «ход ленты»: всё, что крутит время и каналы назад,
стоит слева; всё, что вперёд, — справа; пауза — в центре, как клавиша
Play на деке. Краснеющая при записи ⏺ завершает ряд справа.
Ползунок громкости сжимается при нехватке ширины, а на широком экране
все контролы (дека, громкость, настройки) стоят рядами НАД полосой хода
передачи — контролы никогда не наезжают друг на друга, это проверяет
CI-тест.

Дека живёт в двух местах: на телефоне — крупно по центру кадра
(пауза 64px, остальные 44px), на широком экране — целиком в левом углу
нижней панели, чтобы не перекрывать картинку. В мини-плеере из деки
остаётся только пауза. Автоскрытие контролов прячет деку вместе с
остальными надписями на кадре — достаточно двинуть мышью или коснуться
экрана.

## Запись эфира

Кнопка ⏺ на транспортной деке (правый край ряда): старт записи,
повторный клик — сохранение. Файл
`Канал_ГГГГ-ММ-ДД_ЧЧ-ММ.<ext>` кладётся в папку загрузок **без диалогов**.

**HLS-каналы пишутся сегментами** — теми самыми, что плеер и так скачивает.
Ничего не перекодируется: оригинальное качество, родной звук, нулевая нагрузка
на процессор, файл `.ts` (или `.mp4` для fragmented MP4), который открывают
и VLC, и системные плееры. Работает во всех браузерах, включая Firefox для
Android.

Сегменты уходят на диск через OPFS по мере прихода, поэтому длинная запись не
съедает память; если OPFS недоступен, копятся в памяти. Потолок — 1 ГБ, дальше
запись сохраняется сама.

Запись начинается с границы текущего сегмента — погрешность до нескольких
секунд. Если качество стоит на Auto и плеер переключит уровень посреди записи,
в файле окажутся куски разного разрешения.

**Остальное** (нативное воспроизведение, прямые mp4) пишется перекодированием
в `.webm`: захват прямо с `<video>`, а где он не работает — картинка с канваса
и звук через Web Audio. Каким путём пошла запись, приложение сообщает тостом —
на телефоне консоли нет.

Запасной путь требует, чтобы вкладка оставалась на переднем плане: кадры
снимаются по `requestAnimationFrame`, а он не тикает в фоне.

Записывается то, что слышно: если плеер замьючен, файл получится тихим. Звука
не будет и у каналов, которые играют напрямую (не через hls.js) с чужого домена
без CORS — Web Audio по стандарту отдаёт в этом случае тишину.

> ⚠️ **Перекодирование на Firefox для Android не работает.** Захват `<video>`
> там отдаёт живые дорожки, но энкодер падает с `UnknownError` через секунду,
> а `drawImage` на канвас рисует черноту: декодированное видео лежит в
> аппаратной поверхности, недоступной канвасу. Звук при этом пишется, поэтому
> без проверки получался бы файл с чёрным экраном — приложение распознаёт это
> и останавливает запись с явным сообщением. HLS-каналов это не касается: они
> пишутся сегментами, минуя и канвас, и энкодер.

Если браузер при каждом скачивании спрашивает «Куда сохранить?» — это его
настройка, отключается так:
- **Chrome/Edge**: Настройки → Загрузки → выключить «Перед загрузкой спрашивать,
  куда сохранять файлы»
- **Firefox**: Настройки → Основные → Загрузки → «Всегда спрашивать, где сохранять
  файлы» — снять галочку

## Записанные эфиры: библиотека

Записи не исчезают после остановки: файл кладётся в приватное хранилище
(OPFS), а в сайдбаре появляется раздел **«Записи»** — рядом с «Недавними».
У каждой карточки: канал, передача из телепрограммы (если запись попала
на неё), дата/время, длительность и размер.

- **Клик по карточке** — воспроизведение в плеере. Работает для `.webm`
  и `.mp4`; MPEG-TS (`.ts` из HLS-записи) воспроизводится через hls.js,
  в том числе в Firefox, с перемоткой и без перекодирования файла.
  Если браузер не поддерживает кодек или формат записи, появляется сообщение
  с предложением скачать файл и открыть во внешнем плеере.
  При воспроизведении TS запись загружается в память; большие файлы требуют больше памяти.
- **Кнопка скачивания** на карточке — сохранить файл на диск.
- **Кнопка удаления** — убрать запись вместе с файлом.

## Экспорт избранного в .m3u

Настройки → «Резервная копия» → **«Экспорт избранного в .m3u»** — приложение
соберёт из избранных каналов активного плейлиста валидный M3U-файл
(`#EXTINF` с `tvg-id`/`tvg-logo`/`group-title`), совместимый с любыми
плеерами и с родительским пайплайном [iptv](https://github.com/ozyab09/iptv).
Файл формируется локально в браузере — каналы никуда не отправляются.

## PWA

- **Установка:** Chrome/Android — «Установить приложение» в меню; iOS Safari —
  «На экран «Домой»». Запускается в standalone-режиме без адресной строки.
- **Иконки:** генерируются скриптом `npm run icons` (без внешних зависимостей,
  PNG собирается вручную через `node:zlib`) → `public/icons/`.
- **Оффлайн:** оболочка (HTML/CSS/JS/иконки) кешируется cache-first; плейлист
  и EPG — network-first с отдачей последней успешной копии без сети.
  Живые медиа-потоки **не кешируются** — это осознанное решение.
- **Обновления:** версия SW-кэша штампуется хэшем сборки автоматически, при
  выпуске новой версии бампайте `version` в `package.json` (тест следит,
  чтобы статус в AGENTS.md/ROADMAP.md совпадал) — старые кэши удалятся в
  `activate`. Новая SW-версия подхватывается после перезагрузки страницы.
